# Strings files and string catalogs in Xcode's builds

Observed with Xcode 27.0 (27A266a): `.github/scripts/strings_experiments.py` (`copy`,
`copy-escapes`, `xcstrings`, `xcstrings-build`, `corpus-copy`; the catalogs include the specifier
grammar probe `specifier-*`, `plural-inference-*` and `diagnostic-*`), and every
`.strings`, `.stringsdict` and `.xcstrings` file of the corpus checkouts. nomac reproduces all of
them byte for byte: 44 self-written strings files in three output encodings, 8 of `\U`
surrogate escapes, the 9885 corpus strings files, and the compiled tables and diagnostics of 268
self-written catalogs in three variants and the 49 corpus catalogs (853 compilations).

## Copied strings files (`builtin-copyStrings`)

An iOS build copies each `.strings` and `.stringsdict` file with Swift Build's builtin task:

```
CopyStringsFile <app>/en.lproj/Localizable.strings <src>/en.lproj/Localizable.strings
    builtin-copyStrings --validate --outputencoding binary --outfilename Localizable.strings \
        --outdir <app>/en.lproj -- <src>/en.lproj/Localizable.strings
```

`--outputencoding` is `STRINGS_FILE_OUTPUT_ENCODING` (binary on iOS; every corpus app keeps it),
`--inputencoding` is added when the file reference has an encoding. `nomac builtin-copyStrings`
takes the same arguments (ADR 0250). Builds cannot route Swift Build's in-process
`builtin-copyStrings` to it (ADR 0102), so on Linux the build's own copy runs until Swift Build
is fixed upstream (B-253).

- **Input encoding.** Without `--inputencoding`, a UTF-8 byte order mark means UTF-8, `FF FE` or
  `FE FF` UTF-16, and otherwise valid UTF-8 is UTF-8 (ASCII is reported as UTF-8). The mark is
  not part of the text. A note `detected encoding of input file as Unicode (UTF-8)` (or
  `(UTF-16)`) is printed unless the file is empty. The corpus has 9451 UTF-8 files, 388 UTF-16
  little-endian ones with a mark and 2 UTF-8 ones with a mark; other encodings are BACKLOG B-252.
- **Validation and binary output.** A file of only white space is an empty dictionary; anything
  else is read as a property list (docs/formats/property-lists.md "Reading"); a file that is not
  one fails with `validation failed: Couldn't parse property list because the input data was in
  an invalid format`. Binary output is the property list written as Swift Build writes binary
  property lists (docs/formats/property-lists.md "Binary").
- **Text output.** `UTF-16` is the mark `FF FE` and little-endian code units; `UTF-8` has no mark.
  The text is the input's, unchanged; an empty input gives an empty file.

## String catalogs (`xcstringstool compile`)

Each `.xcstrings` file (not inside an `.lproj` folder other than `mul.lproj`) is compiled into the
target's temporary resources folder, then each output is copied by `builtin-copyStrings`:

```
CompileXCStrings <TempResourcesDir>/ <src>/Catalog.xcstrings
    xcstringstool compile --output-directory <TempResourcesDir> <src>/Catalog.xcstrings
CopyStringsFile <app>/fr.lproj/Catalog.strings <TempResourcesDir>/fr.lproj/Catalog.strings
```

Swift Build plans the outputs with `xcstringstool compile --dry-run`, which prints one output
path per line, in an order that changes from one run to the next (the same catalog, four runs,
four orders); nomac prints them by language, `.strings` before `.stringsdict`. `-l <language>`
(`XCSTRINGS_LANGUAGES_TO_COMPILE`, only set by `installloc`) limits the languages.
`--format stringsdictOnly` writes plain strings into the `.stringsdict` table too.
`--serialization-format binary` is never used by builds (BACKLOG B-250).

### Outputs

For each language with at least one entry, `<language folder>.lproj/<catalog name>.strings`
with the plain strings and `.stringsdict` with the rules, both XML property lists
(docs/formats/property-lists.md "XML"; `.strings` keys in UTF-16 order, `.stringsdict` keys in
Swift's order). Comments, `isCommentAutoGenerated`, `shouldTranslate` (`unlocalized-languages`)
and `version` change nothing.

### Which keys a language gets

- A language gets each key that has a unit for it, whatever the unit's state (`new`,
  `needs_review`, `stale` and `translated` alike).
- The source language: a string extracted from code (`extractionState` absent, `stale` or
  `extracted_with_value`) has its value in the code, so it gets no entry when it has no source
  unit or its source unit is a plain string in state `new`. Manual and migrated strings get
  their source unit whatever its state, or their key as the value when they have none
  (`source-matrix`).
- Another language without a unit gets the key as its value, as a plain string, only for a
  `manual` string whose generated symbol takes arguments: the analysis of "Generated symbols"
  "Arguments" succeeds over its localizations (or its key, without a source unit) with at least
  one argument, whatever the symbol's name (icecubes, owncloud; `unlocalized-variations`,
  `unlocalized-specifiers`). Not for other extraction states, strings without arguments, `%s` or
  any specifier without a Swift type, skipped or inconsistent arguments, nor device or width
  variations or string sets.

### Values

- **Plain strings** go to `.strings`; argument names are dropped: `%(count)lld` and
  `%1$(name)@` are written `%lld` and `%1$@` (`named-arguments`). Only specifiers lose names.
- **String sets** are `#!SET#!_<key>[<index>]` entries of `.strings`.
- **Plural variations** are one rule:

  ```
  <key>: { NSStringLocalizedFormatKey: "%#@value@",
           value: { NSStringFormatSpecTypeKey: NSStringPluralRuleType,
                    NSStringFormatValueTypeKey: <type>, <form>: <string>, ... } }
  ```

  The number is found in the `other` form first, then `zero`, `one`, `two`, `few`, `many`, then
  the same in the source language's value of the key (a plural, or a plain string): the first
  form with a numeric specifier decides. Its type is the specifier's length modifier and
  conversion, without flags, width or precision (`%-3d` is `d`, `%.2f` is `f`). Numbers of two
  types in that form are an error (`Cannot infer format specifier for string group because more
  than one numerical specifier was found`); one type in two positions a warning (`Cannot reliably
  infer argument number for plural variation because %lld is used in multiple positions. Use an
  explicit substitution instead.`), the first position winning. No number anywhere is an error
  (`Plural variation requires referencing the number in the string. ...`). When the number is
  argument N > 1, the format key is `%N$#@value@` and every specifier of the forms is given its
  position (`%@ has %lld` becomes `%1$@ has %2$lld`). Forms are otherwise written as they are,
  invalid specifiers included.
- **Substitutions**: the string's `%#@name@` become `%<argNum>$#@name@` (unchanged without
  `argNum`); each substitution is a variable typed by its `formatSpecifier` (type as above), whose
  plural forms have `%arg` replaced by `%<argNum>$<formatSpecifier>` (`%1$.1f`). A plural form
  that names any variable, a substitution of the string or not, is an error (`Cannot reference
  substitution 'x' from here because it is not a plain string`), reported only when the plural
  has a number (`specifier-68-*`, `diagnostic-variable-in-plural`). Every substitution observed
  has a `formatSpecifier` and plural variations; nomac refuses others (BACKLOG B-264).
- **Device variations**: `NSStringDeviceSpecificRuleType` with every device but `other`; a device
  that varies by plural has the plural rule inline. `other` is the key's plain string in
  `.strings`; it cannot vary further (`Fallback value cannot be further varied`) and is an error
  with `stringsdictOnly`.
- **Width variations**: `NSStringVariableWidthRuleType` with each width's string; a width that
  varies by plural names a top-level rule `<key>|==|width.<width>`.
- Diagnostics are `<catalog real path>: <error|warning>: <message> (<language>: <key>[|==|<variation>.<case>])`,
  errors on standard error and warnings on standard output, in an order that changes from one run
  to the next (`diagnostic-*`); an error writes nothing (Xcode may have written the languages it
  compiled before the error, in its varying order).

### Format specifiers

The specifier grammar probe (`specifier-NN-a`, `-b` and `-p`, three catalogs per candidate): a specifier is `%`,
an optional `N$`, an optional `(name)`, flags from `-+0` only, digits, an optional `.` and digits,
then one of

- integer conversions `d i o u x X D U O` with no length or `hh h l ll q j t z`;
- floating-point conversions `e E f F g G a A` with no length, `l` or `L`;
- `@ c C s S p` with no length.

So `% d`, `%#x`, `%'d`, `%*d`, `%.*f`, `%Ld`, `%ls`, `%l@`, `%n` and `%(x)1$d` are not specifiers,
and `%%` is a literal `%`. Arguments without a position are numbered in order, skipping
positioned ones.

### Language folders

The folder of a catalog language (`language-codes`): `kmr-TR` is `ku-TR` (mastodon). Observed
replacements: `iw` → `he`, `in` → `id`, `ji` → `yi`, `no` → `nb`, `tl` → `fil`, `kmr` → `ku`
(other subtags kept), `i-klingon` → `tlh`, `art-lojban` → `jbo`, `sr-Cyrl` → `sr`. Case: the
language lowercase (`Base` → `base`, `DE` → `de`), a four-letter subtag titlecase (`x-test` →
`x-Test`), a two-letter one uppercase, others lowercase (`en-US-POSIX` → `en-US-posix`).
Identifiers with `_` keep their form (`en_AU`, `es_419`) unless they have a script: `uz_Latn` →
`uz`, `zh_Hans_SG` → `zh_SG`, `az_Cyrl` → `az-Cyrl`. Two catalog languages with one folder give
contents that change from one run to the next. The general rule is BACKLOG B-251.

## Generated symbols (`xcstringstool generate-symbols`)

The GenerateStringSymbols task runs `xcstringstool generate-symbols --language swift
--output-directory <DerivedSources> <catalog>` (`STRING_CATALOG_GENERATE_SYMBOLS`; gomap,
icecubes, mastodon, netnewswire, nextcloud). With `--language swift` it writes
`GeneratedStringSymbols_<catalog>.swift`, with `objc` `SCGeneratedStringSymbols_<catalog>.h` and
`.m`; `--language` may repeat and is required (status 64 without it), and a missing output
directory is an error. Only strings whose `extractionState` is `manual` get symbols: a catalog
without any gets empty files, in both languages; any other state (none, `stale`, `migrated`,
`extracted_with_value`) gets none (icecubes: 441 symbols for 441 manual strings; mastodon's
`Localizable`: 149 for 149 manual and 678 migrated). The Objective-C files are always empty and
draw no diagnostic (322 catalogs, 234 of them with manual strings).

Observed with `strings_experiments.py generate-symbols`: the 49 corpus catalogs, the compile
experiment's catalogs and the `symbols-*` catalogs written for these rules, plus seeded random
catalogs (keys, comments and localizations drawn from the cases below) compared directly.

**File.** A header (`// ` with a trailing space, the file name, `// Auto-Generated symbols for
localized strings defined in “<catalog>.xcstrings”.`, `// `), `import Foundation`, a
`resourceBundleDescription` that is `Bundle.module`'s under `SWIFT_PACKAGE` and
`ResourceBundleClass`'s otherwise, then `nonisolated extension LocalizedStringResource` with one
member per string, by key in Swift's string order, separated by blank lines; no newline at the
end. A catalog other than `Localizable` (exactly) puts its members in `enum <Table>` (`/// Namespace
for strings in file “<catalog>.xcstrings”.`), indented by four more spaces. When no string gets a
member, the file is empty; when the table name cannot be a type name (`Type`, `self`), no file is
written and the tool ends with `Error: error: This table name is too close to a reserved keyword
in Swift. Please rename the file.` after the strings' diagnostics.

**Member.** A doc comment: the string's `comment` with `*/` written `* /` and `/*` written `/ *`,
then a line of five spaces, when there is a comment; then `Localized string for key “<key>” in
table “<catalog>.xcstrings”.`. Comment and key are written as they are, newlines included. A string
without arguments is `static var <name>: LocalizedStringResource` returning
`LocalizedStringResource("<key>", table: "<table>", bundle: resourceBundleDescription)`; one with
arguments is `static func <name>(<parameters>)` passing also `defaultValue:`, the arguments'
interpolations one after the other and nothing else (`"\(arg1)\(count, specifier: "%lld")"`),
`specifier:` left out for `%@`. Parameters are `<label>: <Type>`, or `_ arg<N>: <Type>` without a
label. String literals escape `\0`, `\t`, `\n`, `\r`, `"` and `\`, then every other control or
format character as `\u{<hex>}` (U+0007 is `\u{7}`, U+00AD `\u{AD}`); `'`, U+2028 and private use
characters stay.

**Names.** A key becomes a lower camel case name:

- A `%#@name@` without a position first gets its argument number, unless a specifier written
  with a position has that number (`%@ %#@x@` is `%@ %2$#@x@`, `%1$@ %#@x@` stays). Then every specifier but a positioned `%N$#@name@` is a word break, as are
  `_`, U+200B and characters with a Unicode scalar a Swift identifier cannot hold (so a space and
  the combining mark after it are one break; `$` is kept). What a positioned variable leaves
  stays (`a%#@x@b` is `a1$XB`). Xcode finds specifiers scalar by scalar: `%@` followed by a
  combining mark is still one, which nomac does not see yet (B-230).
- `'` and `’` between two kept characters are dropped (`don't stop` is `dontStop`); elsewhere they
  break words (`a''b` is `aB`).
- A word also ends after a character that is neither uppercase nor lowercase (digits, `$`, `·`,
  `²`, emoji, CJK, titlecase `ǅ`): `a1b2` is `a1B2`, `x 2nd` is `x2Nd`.
- The first word's leading run of characters that uppercasing leaves unchanged (uppercase
  letters, and lowercase ones without an uppercase form, `ꜰ`, `ʰ`, `ª`) is lowercased:
  `URLLoader` is `urlloader`, `HelloWorld` `helloWorld`, `iOS` stays. Every later word: when its
  first character is in such a run, that character stays and the rest of the run is lowercased
  (`URL` is `Url`, `İ` stays `İ`); otherwise a lowercase first character is uppercased (`ǆ` is
  `Ǆ`, `ß` is `SS`) and anything else stays (`ǅ`).
- When `_` or U+200B comes before the first word (after any other separators), it is kept once as
  a prefix and the first word is treated as a later one (`__COLUMN__` is `_Column`, `-_x` is
  `_X`, `\u{200B}ab` is `\u{200B}Ab`).
- A name whose first scalar cannot start an identifier gets `_` (`1 apple` is `_1Apple`, `$money`
  is `_$Money`).
- A key or name that is a Swift keyword gets backquotes (the key `Any` is `` `Any` ``, `Init` is
  `` `init` ``; keywords: `_ Any Self as associatedtype await borrowing break case catch class
  consuming continue default defer deinit do else enum extension fallthrough false fileprivate
  for func guard if import in init inout internal is let nil nonisolated open operator
  precedencegroup private protocol public repeat rethrows return static struct subscript super
  switch throw throws true try typealias var where while`; not `package`, `actor`, `some`,
  `async`, `any`). `self`, `Type` and `Protocol` are errors: `This key is too close to a reserved
  keyword in Swift. Please rename the key.` An empty key is `Unable to derive a symbol name from
  this key.`, one with no kept character adds ` It only contains characters that are invalid in
  Swift.`

A table name becomes a type name the same way, but every word only gets its first character
uppercased (`x URL ABC def` is `XURLABCDef`, `LOCALIZABLE` stays).

Two strings whose members have the same name and the same parameter labels and types are errors
(`This string key would generate the same symbol as “a”, “b”, and “c”. Please change the key or
disable symbol generation for this string.`, the others in key order); a property and a
function, or functions with other labels or types, may share a name. Strings that fail for
another reason take no part.

**Arguments.** Each localization's arguments, the source language's being the key when it has
none:

- A specifier without a position takes the next number; positioned ones do not count. A
  `%#@name@` is its substitution's `formatSpecifier`, labeled with the name, at its own position,
  else the substitution's `argNum`, else the next one; a later `%#@name@` of the same name is the
  same argument. A `%#@name@` without such a substitution takes a number and no argument. Only
  the localization's own substitutions count, not those inside variations.
- In a substitution's forms, `%arg` is an unlabeled argument of the substitution's type at its
  `argNum`, else at the next number, numbers starting at the substitution's position (`%arg %@`
  of a `%2$#@x@` is 2 and 3). The forms' other specifiers only fill numbers nothing else gives, and
  must agree within their form. Unreferenced substitutions count too, from 1.
- `%(name)lld` is labeled with the name. Arguments at one number with different types, or
  different `%(name)` names, or one name at two numbers, are an error: `A symbol cannot be
  generated for this string because format specifiers are inconsistent.` The key standing for a
  missing source localization is never inconsistent: the last specifier at a number wins.
- Across localizations each number takes the argument of the source language, else of the last
  other language in case-insensitive order (`fr-CA` over `fr`, `Base` over `ar`; B-231 for the
  exceptions). Numbers with a gap are an error (`Some argument numbers were skipped. Make sure that
  each argument number is referenced in the translation of at least one language.`).
- Types: `%@` `String`, `%d` `Int32`, `%u` `UInt32`, `%f` `Float`, `%g` `Double`, `%ld` and
  `%lld` `Int`, `%lu` and `%llu` `UInt`, `%lf` `Double`; any other specifier the catalog grammar
  accepts is an error (`Unable to create a Swift type from the format specifier “%i”.`, the
  specifier as written without its position, `%(name)s` for a substitution, `%arg` for one
  without `formatSpecifier`). The interpolation's `specifier:` is the specifier without position
  or name (`%.2f`, `%-5d`).
- Labels are names derived as for keys (`x y` is `xY`, `class` is `` `class` ``); a substitution
  named `self`, `Type` or `Protocol` gets no label and the warning `The format specifier label
  “self” is too close to a reserved keyword in Swift. Please rename it. (<language>:
  <key>|==|substitutions.self)`, the language in its `.lproj` form (`base`), unless one of the
  string's localizations is inconsistent.

Errors go to standard error and warnings to standard output, `<catalog path>: error: <message>
(allLocales: <key>)`, in an order that changes from run to run; nomac prints them by key. The
tool exits 1 after any error, having written the members of the other strings.
