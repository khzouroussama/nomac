Workstream: React Native and Expo apps that nomac is measured on but never developed against, so
that the fixes made for expo-default and rn-bare (docs/state/react-native.md) are checked for overfitting.
Differences found here are triaged to the workstream that owns them, not fixed here. Branch
`corpus/rn-holdout`. BACKLOG B-050–B-059, ADRs 0050–0059.

## Xcode's references

`rn_holdout_experiments.py capture` writes `capture_reference.py`'s layout to
`refs/<configuration>/<id>` as expo_experiments.py does (PIF, `-list` and every settings capture
once per app, the build per configuration, `generic/platform=iOS` without signing), and `archive`
adds the Release archive with ad-hoc signing and its `debugging` export (`archive/`), whose
signing and export `nomac verify` replays.

The builds run without `sandbox-exec`. Inside it, Swift macros fail: `swift-plugin-server`
applies a sandbox of its own, which cannot be nested in another profile ("sandbox_apply:
Operation not permitted", then "external macro implementation type 'SwiftUIMacros.StateMacro'
could not be found ... produced malformed response"); one `@State` in a file typechecked with
`swiftc` reproduces it, and react-native-pager-view's Swift uses `@State`. lsof samples every
socket the build's processes open instead (`build/network.log`, `archive/network.log`).

The checkout is restored after each build in one `git checkout` (capture_reference.py): the
script phases that swap React Native's xcframeworks per configuration rewrite tens of thousands
of headers in `Pods/`, and one checkout per file took over 20 minutes for 9,377 of them.

## B-182 against prebuilt React Native

`rn_holdout_experiments.py mangling` lists, from a reference's products, the undefined symbols
of the app's executables and of every static library compiled from source whose template
arguments point into objects (`Xad...`, the forms B-182 changes), and which of them the embedded
frameworks define. Each would be a reference the Linux-compiled code spells otherwise.

| App | Embedded frameworks | Their exported symbols of that form | Undefined in code compiled from source | Defined by the frameworks |
|---|---|---|---|---|
| rn-bare (Release, Debug) | React, ReactNativeDependencies, hermesvm | 6 | 0 | 0 |
| expo-default (Release, Debug) | 14 | 6 | 0 | 0 |
| rn-libs (Release, Debug) | React, ReactNativeDependencies, WebRTC, hermesvm | 6 | 0 | 0 |
| expo-modules (Release, Debug) | 17 | 6 | 0 | 0 |
| rn-native (Release, Debug) | React, ReactNativeDependencies, hermesvm | 6 | 0 | 0 |

React's six are `concreteComponentDescriptorConstructor<...ConcreteViewShadowNode<&...ComponentName>...>`
for its own components. Libraries' Fabric components (react-native-svg, -screens, -pager-view,
-webview, -safe-area-context) instantiate the templates with their own names and define them
themselves, so B-182 changes symbol names inside the app but no reference across the prebuilt
boundary in these apps.

These runs used a toolchain installed before the clang workstream's ADR 0170 (Clang 4's C++ ABI
from swift.org's clang, docs/state/clang.md), so their Linux objects still have the other
mangling; the next Linux runs reinstall it.

## Reproduce

```sh
export DEVELOPER_DIR=/Applications/Xcode_27.app/Contents/Developer
S=.github/scripts/rn_holdout_experiments.py
python3 $S generate                      # online: npm, CocoaPods, JitsiWebRTC's xcframework
python3 $S capture                       # Xcode's references, Release and Debug
python3 $S archive                       # Release archive and debugging export
python3 $S verify --nomac .build/debug/nomac
python3 $S mangling                      # B-182's references across the prebuilt frameworks
python3 $S triage <build log>
```

On Linux: the `nomac-rnh` volume holds this branch's sources and build (`/work/src`,
`/work/build`, built offline with the SwiftPM checkouts copied in), cctools-port's and LLVM's
tools (`/work/cctools`, `/work/llvm-tools`, copies of the Expo workstream's) and a developer
directory installed by this nomac (`/work/devdir`); `rnh/` holds the Linux Node, links to the references and nomac's reports. `~/nomac-out/wt-scratch/rn-holdout/linux/verify.sh`
(outside the repository) clones each app named at the Mac's path, runs `verify` in a container
without network and removes the clone (2 to 3 GB each); the build container is only needed to
rebuild nomac:

```sh
docker run -d --name nomac-rnh -v nomac-rnh:/work -v nomac-build:/ref:ro nomac-linux:6.4.1-noble sleep infinity
git ls-files -z | tar --no-xattrs --no-mac-metadata --null -T - -cf - | docker exec -i nomac-rnh tar -xf - -C /work/src
docker exec nomac-rnh sh -c 'cd /work/src && swift build --scratch-path /work/build -debug-info-format none --skip-update -j 4'
docker exec nomac-rnh sh -c 'cp -a /ref/xcode/Xcode_27.app /work/devdir/ && /work/build/debug/nomac toolchain install \
  /ref/toolchains/swift-6.4.0-RELEASE-ubuntu24.04-aarch64/usr --llvm-tools /work/llvm-tools \
  --developer-dir /work/devdir/Xcode_27.app/Contents/Developer'
R=$HOME/nomac-out/wt-scratch/rn-holdout
docker run -d --name nomac-rnh-verify --network none -v nomac-rnh:/work \
  --mount type=volume,src=nomac-rnh,dst=/Applications/Xcode_27.app,volume-subpath=devdir/Xcode_27.app,readonly \
  --mount type=volume,src=nomac-rnh,dst="$R",volume-subpath=rnh \
  -v $R/apps:/mac-apps:ro -v $R/refs:/mac-refs:ro -v $R/linux:/linux:ro -e HOME_MAC=$HOME \
  nomac-linux:6.4.1-noble sleep infinity
docker exec nomac-rnh-verify bash /linux/verify.sh <app ...> [--configuration C]
```
