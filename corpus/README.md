# The verification corpus

The corpus is how nomac measures itself: a curated list of real open-source iOS apps, each
pinned to a commit, built with Xcode on GitHub's macOS runners (the reference) and with
nomac (the candidate). A component counts as working only to the extent that its output
matches the reference across the corpus.

## Files

- `corpus.json`: the manifest. It names the reference Xcode (`xcode`), maps the progress
  lines to the check kinds that measure them (`progress`, docs/VERIFICATION.md "Progress") and
  lists the apps.
- `scripts/capture_reference.py`: captures the Xcode reference for one app on a Mac (`--build`
  adds the Xcode build to a reference captured with `--skip-build`, `--archive` an ad-hoc archive
  with its codesign steps and its export).
- `scripts/matrix.py`: turns the manifest into the CI matrix.
- `RESULTS.md`: per-app and per-check-kind results and the tools' refusals, regenerated by CI.

## Manifest fields

| Field | Meaning |
|---|---|
| `id` | Stable identifier used in artifact names and results |
| `repository`, `commit` | Where the app comes from, pinned to an exact commit |
| `license` | The app's license, as stated in its repository |
| `container` | The `.xcodeproj` or `.xcworkspace` to load, relative to the repository root |
| `tier` | `A`: stock Xcode plus SwiftPM. `B`: also needs CocoaPods, Carthage, submodules or a bootstrap script. `C`: also needs a foreign toolchain (node, flutter, gradle, cmake) |
| `prepare` | Shell commands run in the checkout before loading (tier B and C) |
| `submodules` | Whether to initialize git submodules |
| `build`, `test` | The scheme and configuration used for the reference build and the device test run; a build's `settings` are build setting overrides and its `options` further xcodebuild options, both passed to xcodebuild and to nomac alike |
| `exercises` | File types and features the app exercises |
| `notes` | Why the app is in the corpus |

## Capturing references

The `reference` workflow runs on every change to the manifest or the capture scripts, and
on demand (Actions → reference → Run workflow, optionally with a comma-separated list
of app ids). Locally on a Mac with the reference Xcode selected:

```sh
python3 corpus/scripts/capture_reference.py retro-rampage /tmp/reference
```

What is captured and how it is compared is specified in docs/adr/0004-reference-artifacts.md.
